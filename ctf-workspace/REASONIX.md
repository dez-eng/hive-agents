# CTF 专项工作区

本工作区用于 CTF 解题。所有规则对本目录下的会话强制生效。

## 铁律（违反即视为答错）

1. **禁止一句话结论。** 不允许出现「这是 SQL 注入」「这是 RSA 小公钥攻击」然后结束。必须给出完整可复现的解题过程。
2. **禁止凭空猜测。** 每个判断必须标明依据：源码行号、报错原文、响应差异、数学推导，四者之一。
3. **禁止跳过技能库。** 拿到题目第一件事是查技能，不是凭记忆回答。
4. **禁止未验证交付。** 给出 payload 或脚本后，必须说明如何验证；能本地跑的就跑一遍。

## 强制解题流程

### 第 0 步：识别题型

```
use_capability({ action: "search", query: "<英文关键词>" })
```

或直接读路由：

- `00-skill-router` — 全量技能地图，先看这个
- `000-2026-security-skills-hub` — 2026 安全技能总索引（1083 个）

### 第 1 步：加载对应题型技能

| 题型 | 技能 |
|---|---|
| Web / API | `ctf-web` |
| 密码学 | `ctf-crypto` |
| 二进制利用 | `ctf-pwn` |
| 逆向 | `ctf-reverse` |
| 取证 | `ctf-forensics` |
| 隐写 / 杂项 | `ctf-misc` |
| 情报 | `ctf-osint` |
| 恶意样本 | `ctf-malware` |
| AI/ML | `ctf-ai-ml` |
| 综合调度 | `solve-challenge` |

具体漏洞类型另有细分技能，例如 `sqli-sql-injection`、`ssti-server-side-template-injection`、`rsa-attack-techniques`、`jwt-oauth-token-attacks`、`path-traversal-lfi`、`deserialization-insecure`。搜索关键词即可命中。

### 第 2 步：侦察

先收集事实，不做假设：

- HTTP 应用：抓一份正常请求响应，看 header、cookie、隐藏路由、`/robots.txt`、`/admin`、`/.git/`、`/.env`
- 给源码：先枚举路由和入口，找 sink（危险函数）与 source（用户输入）的交汇点
- 给二进制：`file`、`checksec`、`strings`、反编译
- 给密文：识别算法（长度、字符集、结构），再查对应攻击

### 第 3 步：构造最小验证

先拿一个最小 primitive（读一个文件、绕一个鉴权、造一个合法 token），再扩展成完整利用。不要一上来就写全链 exploit。

### 第 4 步：输出完整解答

必须按以下结构，缺项视为不合格：

```markdown
## 题目判断
<题型 + 具体漏洞类型 + 一句话说明为什么是它>

## 判定依据
<源码片段行号 / 报错原文 / 响应差异 / 数学推导，至少一条硬证据>

## 完整利用
<可直接执行的完整脚本或 payload，含所有 import 和参数>

## 验证方式
<怎么确认成功，预期输出是什么>

## Flag 位置
<flag 在文件/数据库/环境变量/响应头中的具体位置>
```

## 工具使用要求

- 能用命令验证的，不要用推理代替。有 `curl` 就发请求，有 `python` 就跑脚本。
- 脚本写到工作目录，命名 `solve.py` / `exploit.py`，不要留在临时目录。
- 失败要报告失败原因和下一次尝试方向，不要静默重试。
- 涉及网络目标时，只攻击题目给定的靶机地址，不做范围外扫描。

## 常见失误自查

交付前逐条检查：

- [ ] 我把「可能是」当成「就是」了吗？
- [ ] 我的 payload 有没有实际跑过或推演过每一步？
- [ ] 我解释了为什么这个 payload 能生效吗？
- [ ] 读者能照着我的步骤复现吗？
- [ ] 我有没有漏掉更简单的解法？

## 兜底

如果技能库和本机工具都不足以解题，明确说明卡在哪一步、缺什么信息或工具，不要用模糊语言掩盖。
