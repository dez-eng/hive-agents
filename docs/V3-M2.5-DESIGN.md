# hive v3 · M2.5 设计 —— 实用化四件

> 一句话：M2 把「能用什么、谁批的」立住了，但真要拿它干活还差四件 ——
> **精确编辑、循环护栏、上下文压缩、能跑命令**。
>
> 本文只定接口与边界，§8 的待拍板项定了之后才动代码。
> 四件做完，hive 从「能演示多 agent」变成「能当日常工具用」。

## 0. 范围

**做**：

| # | 件 | 归到哪 |
|---|---|---|
| 1 | `edit_file` —— 精确替换，不再整文件重写 | `fs` capability |
| 2 | 工具循环上限 + REPL 也上预算闸门 | 执行层（`agent.ts` + 会话层） |
| 3 | 上下文压缩（超阈值丢老轮次 + 零 API 摘要） | `agent.ts` 发送前 |
| 4 | `bash` —— `shell` capability 从"只声明"变真实现 | 新 capability + 网关 `exec` |

**不做**（仍留 M3，见 V3-PLAN §6）：沙箱 L2（子进程隔离 / env 清理 / cwd 锁定）、
A→B 往返、并行借调、按 agent 核账、web / MCP / skill / 多 provider。

## 1. `edit_file`（归 `fs`）

### 1.1 为什么要它

现在只有 `write_file`（整文件覆盖）。改一个 300 行的文件里的一行，模型得把 300 行
**全部重新吐一遍** —— 输出 token 全价、还可能顺手改错别处。这是当前最贵也最不安全的操作。

### 1.2 接口

```ts
edit_file(path: string, old_string: string, new_string: string, replace_all?: boolean)
```

| 情况 | 行为 |
|---|---|
| `old_string` 恰好出现 1 次 | 替换，回 `OK: 已替换 path:行号（a → b 字符）` |
| 出现 0 次 | 拒绝，回 `ERROR: 没找到这段（文件 N 行）` —— **不改文件** |
| 出现多次且没给 `replace_all` | 拒绝，回 `ERROR: 出现 N 次（行 12、48、99…），要么给更长的上下文，要么加 replace_all` |
| `replace_all: true` | 全部替换，回替换了几处 |
| 文件 > 256 KB | 拒绝，提示改用 `write_file`（大文件全量重写本来就该是显式选择） |

**唯一匹配才动手** —— 这是 `edit_file` 的全部价值所在。宁可让模型重试，也不猜它想改哪一处。

### 1.3 权限

`kind = 'fs.write'`，走网关（与 `write_file` 同一条规则）。工具内仍对 roots 兜底。

## 2. 循环护栏与预算闸门

### 2.1 两件必须一起做

M2 之后我读代码发现两个洞，合起来是"失控通道"：

1. **图是自环**：`agent → tools → agent`，没有步数上限
2. **REPL 的对话没有预算闸门**：`budgetTokens` 只有借调子任务传了，
   自己聊天那条路径是空的

单有闸门挡不住"每步都很便宜、但能跑一百步"的失控；单有步数上限挡不住"一步就烧掉一整轮预算"。

### 2.2 工具步数上限

- `MAX_TOOL_STEPS = 16`（可用 `HIVE_TOOL_STEPS` 调，0 = 不限）：**一次 `run()` 内**，工具批次最多执行 16 次
- 超限时：**不再执行工具**，给每个调用回一条 `ERROR: 本轮工具调用已达上限（16 次），停下来汇报现状`
- 于是模型拿到"停"的信号后自然收尾（它会生成一段文字，`route` 看到没有 `tool_calls` 就 END）
- 借调子任务有自己的一份计数（各自 `run()`），互不影响

> 为什么不是"直接掐断"：留一条 `ToolMessage` 是必须的 —— 历史里出现没有回应的
> `tool_calls`，下一轮请求会被模型侧拒（"tool_calls must be followed by tool results"）。

### 2.3 REPL / run 的预算闸门

- 新环境变量 `HIVE_TURN_BUDGET`（token，**默认 20000**，`0` = 不封顶）
- `repl.ts` 与 `cli.ts` 的 `run` 路径都把它传进 `TurnRequest.budgetTokens`
- 触发时行为与借调一致：`callModel` 之前熔断，本轮以 `budgetHit` 收尾，footer 照常显示
- 熔断时额外打一句人话：`[本轮熔断（超 20000 token）—— 说「继续」就接着跑]`，
  免得切断看起来像出错

## 3. 上下文压缩

### 3.1 先说清根本冲突（这条决定整个设计）

压缩 = 改 prompt 的**中段**。而缓存是按前缀算的 —— 中段一变，**后面全部作废**。
所以压缩不可能"每轮微调一点点"，只能**攒够了做一次，做一次付一次全量重算**。

这跟角色片贴尾（落在必然未命中的尾巴里）不一样：尾巴是"末轮新内容"，
压缩动的是"历史开头"。要认这个代价。

### 3.2 触发（免费且准确）

**用上一轮的真实 `inTok` 当尺子**，不额外估算、不额外调用：

```
上一轮 inTok > COMPRESS_AT（默认 24000）  →  这一轮发送前压一次
```

拿不到上一轮（新会话）就不压。

### 3.3 保留与丢弃

- 保留最近 `KEEP = 16` 条消息
- **切点必须对齐到 `HumanMessage` 边界**：每轮都以用户消息开头，从那里切才不会
  把 `tool_calls` 和它的 `ToolMessage` 拆散（拆散了模型侧直接报错）
- 丢掉的那段压成**一条摘要消息**（插在保留段之前）

### 3.4 摘要怎么来（零 API）

不调模型，纯启发式：把丢掉那些轮次的问句/答句各取前 60 字，按时间顺序列，最多 20 行；
超过就只留计数。形如：

```
[已压缩 14 轮对话 · 以下是每轮要点]
· 问「用 grep 找 DEFAULT_SPEC」→ 答「src/core/policy.ts:41」
· 问「把 hello 写进 a.txt」→ 答「已写入 a.txt」
…（其余 4 轮省略）
```

### 3.5 摘要必须稳定

摘要文本**一旦生成就固定**，不随新轮次变化 —— 否则等于每轮都在改中段，
那第 3.1 节的代价就不是"一次"而是"每轮"。

### 3.6 不动 checkpoint

压缩只发生在**发送前**（和 `SYSTEM` 的处理方式一样）：`state` / `checkpoint` 一个字节不改。
所以 `/history`、`/turn`、续会话看到的仍是完整历史，只有发出去的那份被裁过。

## 4. `bash`（`shell` capability 落地）

### 4.1 执行方式：**不给 shell**

用 `spawn(bin, args)` 直接执行，**不走 `sh -c`**。

理由很直接：走 shell 的话，白名单形同虚设 —— `ls; rm -rf /` 的第一个词是 `ls`，
白名单放行，后面那半句照跑。不给 shell，白名单才成立。

**代价（要认）**：管道 `|`、重定向 `>`、通配符 `*`、`&&` 全都不支持。
需要这些的时候，让它写成脚本文件再用白名单里的解释器跑 —— 或者等 M3 的 L2 真隔离。

### 4.2 判定链（沿用 M2 的五步，只是 `exec` 那一步真的接上了）

```
1. 身份装没装 shell          → AGENTS[x].capabilities
2. agents.X.exec = allow?    → policy 规则表（默认 deny）
3. 命令在 exec.allowCommands 里?（取 basename 精确比对）
4. 执行：timeout 10s（可传参，上限 30s）· 输出合计上限 4000 字符 · cwd = roots[0]
```

M2 里第 3、4 步的代码已经写好、只是没有工具能触发它；这一步就是把线接上。

### 4.3 诚实的边界（必须写在文档里，不能假装没有）

- **白名单是"信任这个命令"，不是"限制这个命令的作用范围"**：
  `ls` 一旦被信任，它就能列任意目录 —— `roots` 对 `exec` **没有意义**（这是 L2 要解决的）
- 命令能读到进程环境（`env` 这种命令会吐出来）—— env 清理也是 L2
- 命令能写文件，**绕过网关的 `fs.write`**（网关只管工具调用，管不了子进程）

所以 `exec` 的默认动作必须是 **deny**，且白名单默认值本身就是一个拍板项（§8 第 3 问）。

### 4.4 谁装 `shell`

`AGENTS[x].capabilities` 加不加 `shell` —— 待拍板（§8 第 4 问）。
注意：**装了不等于能跑**，能不能跑由 policy 决定（这就是 M2 那套"两层"的用法）。

## 5. 缓存影响

| 改动 | 谁的前缀变了 | 代价 |
|---|---|---|
| `fs` 加 `edit_file` | A / B / C / D（都装 fs） | 各自冷启动一次 |
| 新 `shell` capability 加 `bash` | 装了 shell 的那些 | 各自冷启动一次 |
| 压缩 | 触发的那一轮 | 一次全量重算（固有代价，见 §3.1） |

稳态增量：`edit_file` 约 +250 字符、`bash` 约 +300 字符（含 schema JSON，实测后复核）。

## 8. 待拍板清单

| # | 议题 | 决定 | 落到哪 |
|---|---|---|---|
| 1 | 工具步数上限 | **16**（`HIVE_TOOL_STEPS`，0 = 不限） | §2.2 |
| 2 | `HIVE_TURN_BUDGET` 默认 | **20000 token**（0 = 不封顶），熔断时打一句「说『继续』就接着跑」 | §2.3 |
| 3 | `exec` 白名单默认 | **空**（谁都跑不了）+ 支持 `"*"` 表示不限（仍要 `agents.X.exec = allow`） | §4.3 |
| 4 | 谁装 `shell` | **全员**（A/B/C/D）—— 装 ≠ 能跑，policy 兜底 | §4.4 |
| 5 | 摘要方式 | **零 API 启发式**（不调模型，拼各轮首句） | §3.4 |

> 第 1 条的取向：16 允许一轮走完一条长链，但**长任务的第一选择仍是「多轮推进」**——
> 每轮是一笔可核对的消费，而不是一个越来越大的黑洞。第 3 条沿用 M2「默认拒绝」的调子：
> 想用命令，自己往 `.hive/policy.json` 填一行（或写 `"*"` 全放开，自担风险）。

## 9. 真机验证结论（2026-10-16，deepseek-flash，共约 $0.004）

| 验的东西 | 结果 |
|---|---|
| `edit_file` | C 身份把 `.m2p-probe.txt` 的 `line-two` 改成 `line-two-CHANGED`，**第一行未动**；$0.000158 · 命中 72% |
| `bash` 默认（白名单空） | A 被拒，footer 显示「拒1」；$0.000248 |
| `bash` 放行（`exec.allowCommands: ["git"]` + `agents.A.exec: allow`） | 真跑出 `git version 2.52.0.windows.1` + `[退出码 0]` |
| 步数上限（`HIVE_TOOL_STEPS=1`） | 第一批工具后停下，打出「本轮工具调用到上限 1 批，已停下 —— 说『继续』就接着跑」 |
| 压缩（`HIVE_COMPRESS_AT=800` / `KEEP=4`） | 第 3 轮「丢掉 2 条旧消息」、第 4 轮「丢掉 4 条」—— 真触发，且只在超阈值时压 |

真机才暴露的三件事（前两件已修）：

1. **压缩的尺子不能用本轮的 `meter`** —— `meter` 是每轮的计量器，第一次 `callModel` 时
   `inTok` 恒为 0，所以初版压缩**永远不触发**。改成 `HiveAgent` 按 thread 记住上一轮的
   `inTok`（`prevInTok`）。
2. **模型会凭历史放弃调用工具** —— 上一轮被网关拒过之后，下一轮它直接说「跑不了」，
   连工具都不调（**footer 没有「拒N」**正是这一点暴露出来的）。所以验证某个工具要
   `/new` 开新会话，或者明确点名「调用 X 工具」。
3. **Git Bash 下给 `npx` 用前缀传 env 会丢** —— `HIVE_POLICY=x npx tsx …` 读不到配置，
   改成 `export HIVE_POLICY=x` 才对。这与 hive 无关，是 Windows npx 包装器那一层的环境坑。
