# hive v3 · M2.6 设计 —— 沙箱加固两条（env 清理 + realpath 校验）

> 一句话：M2.5 把 `bash` 接上了，但同一次交付也暴露两个洞 ——
> **子进程继承全部环境变量（含 API key）**、**路径检查不解析符号链接**。
>
> 两件都不大，但都属于「默认配置下看不出来、一旦放开白名单就立刻能利用」的口子。
> 本文只定接口与边界，§6 的待拍板项定了再动代码。

## 0. 现状（代码事实，不是设想）

1. **env 继承**：`bash.ts` 里 `spawn(bin, args, { cwd, shell: false, windowsHide: true })`
   **没有传 `env`** → 子进程拿到整个 `process.env`。而 `cli.ts` 用 `loadEnvFile()` 把
   `.env` 读进了 `process.env` —— 所以只要白名单里有一条能读环境的命令
   （`env`/`printenv`/`node -e "…"`），`DEEPSEEK_API_KEY` 就被打印出来了。
   **等于我们主动把钥匙递过去。**
2. **符号链接穿透**：`tools.ts` 的 `read_file`/`write_file`/`edit_file`、`search.ts` 的
   `scopeRoots`，都只做 `resolve()` + 字符串前缀比较（`policy.ts` 的 `withinRoots`），
   **不解析 `realpath`**。项目里放一个链接指向 `C:\Users\you\.ssh`，`read_file link/id_rsa`
   的字符串路径仍在 roots 内 → 放行 → 实际读到外面。

（`search.ts` 的 `walkFiles` 本身**不跟链接**：`Dirent.isFile()` 对符号链接为 false。
所以 grep/glob 的遍历是安全的，只需把 roots 解析一遍。）

## 1. env 清理

方案：`spawn` 时**显式传 `env`**，只给一份最小集：

```
PATH  PATHEXT  SystemRoot  windir  COMSPEC  TEMP  TMP
HOME  USERPROFILE  LANG  LC_ALL  TZ  SHELL  USER
```

（`SystemRoot`/`windir`/`TEMP` 在 Windows 上不给会让不少程序直接失败；`PATHEXT` 留给
以后可能用到的 `.cmd` 场景。）

**双保险**：无论谁在保留名单或逃生舱里，只要变量名匹配
`/(KEY|TOKEN|SECRET|PASSWORD|CREDENTIAL)/i` 就**一律抹掉**。

**逃生舱**：`HIVE_BASH_ENV_KEEP=GOPATH,JAVA_HOME` —— 显式列出才透传，**且仍受敏感词过滤**
（写在名单里也抹不掉某条规则，是刻意的：逃生舱是给「工具需要它」，不是给「我要把密钥塞回去」）。

> ⚠ 诚实边界：env 清理堵的是「**继承**」这一条 —— 我们不再主动把钥匙递过去。
> 它**不**阻止被信任的命令去读它本来就有权读的文件（`.env` 文件本身还在磁盘上，
> 只要白名单里有 `cat` 就照样能读）。那属于 §3 说的 L3 范畴。

## 2. realpath 校验

新增 `withinRootsReal(target, spec)`（`policy.ts`），替换工具层的兜底调用：

| 情况 | 做法 |
|---|---|
| 目标已存在 | `realpathSync(target)` 后比较 |
| 目标不存在（准备新建） | `realpathSync(dirname(target))` 再拼回基名 |
| roots 自身 | 创建 policy 快照时一并 `realpath`（cwd 可能是链接） |
| `realpathSync` 抛错（权限 / 竞态） | **按拒绝处理**（保守侧） |
| Windows | 比较时大小写不敏感；剥掉 `\\?\` 长路径前缀 |

语义：**解析之后仍在 roots 内就放行** —— 指向 roots 内部其它位置的链接照常可用
（有些仓库内部就是这么组织的），只拒绝「解析后跑到 roots 外面」的链接。

调用点：`read_file` / `write_file` / `edit_file` 的工具内兜底、`search.ts` 的 `scopeRoots`、
`bash.ts` 的 `cwd`。网关（`checkAction` 里的 `roots` 判定）也换用它，保证**判定与兜底同源**。

## 3. 不做的（留给 L3 / 以后）

- 子进程降权（Windows 受限令牌 / Job Object）、容器与微虚拟机
- `bash` 白名单的**参数级**约束（只在 §6 问一句要不要顺手支持两词形式）
- 网络隔离（`net` 至今未实现）
- 「人在环」的 `ask` 通道（M2 已定为按拒绝处理）

## 4. 影响面

- **完全不碰 prompt → 零缓存影响**（两条都在执行层；工具 schema 与 `STABLE_PREFIX` 都不动）
- `.hive/policy.json` 无需改（除非要用逃生舱 `HIVE_BASH_ENV_KEEP`）
- 现有测试应当继续通过：越界用例（`'../../etc/passwd'`、`join(dir,'..','x')`）本来就该被拒

## 5. 测试计划（零 API）

新文件 `test/sandbox.test.ts`：

| 用例 | 断言 |
|---|---|
| env：子进程看不到密钥 | 注入 `HIVE_TEST_FAKE_SECRET` + 真 `DEEPSEEK_API_KEY`，命令回显环境 → 两者都不出现 |
| env：保留项在 | `PATH`（或 Windows 的 `SystemRoot`）在子进程里可见 |
| env：逃生舱 | `HIVE_BASH_ENV_KEEP=HIVE_TEST_SAFE` → 透传；但 `HIVE_TEST_FAKE_SECRET` 写了也照样抹掉 |
| realpath：普通文件 | roots 内正常文件照常放行 |
| realpath：指向外部的链接 | **被拒**（Windows 上 `symlinkSync` 需要权限 → 用 `junction` 建目录联接，或在无权限时 `t.skip()` 并注明平台限制） |
| realpath：`realpathSync` 失败 | 按拒绝处理 |
| realpath：roots 本身是链接 | 仍能正常工作（不把自己锁在门外） |

## 6. 待拍板

| # | 议题 | 决定 | 落到哪 |
|---|---|---|---|
| 1 | env 保留集 | **最小白名单 + 逃生舱**（`HIVE_BASH_ENV_KEEP`），敏感词过滤优先于逃生舱 | §1 |
| 2 | realpath 严格度 | **只拒「解析后跑到 roots 外面」的链接** —— 指向仓库内部的链接照常可用 | §2 |
| 3 | `exec.allowCommands` 粒度 | **支持两词形式**：命令前 N 个词**前缀精确匹配**（白名单可写 `"git"`，也可写 `"git status"`） | §1 / policy.ts |

> 第 3 条与「不给 shell」是配套的：正因为命令是我们自己切成词直接 `spawn` 的，
> 「前 N 个词精确匹配」才有确定含义；如果走 `sh -c`，这套规则立刻失去意义。
