# hive v4 · M4.2b 剩余 —— web fetch（域名白名单）

> 一句话：给模型一件**只读、只 GET、只去白名单域名**的取网页工具；
> 工具 schema 进前缀（按身份装配），结果进 ToolMessage，不走 skill 的贴尾通道。
>
> 位置：`web` capability 在 `CAPABILITY_ORDER` 里早就占了一格（排在 `shell` 之后、
> `skill` 之前），M2 起一直只声明不实现。这次把它填上，顺序不动 —— 动了就是
> 给所有装了 `web` 之后的 capability 的 agent 作废一次前缀缓存。

## 0. 现状（代码事实）

1. `policy.ts` 已经有 `net` 动作和 `net.allowDomains`（默认空 = 全禁），
   `checkAction` 里也已经有一段精确匹配的 net 判定（`policy.ts:558` 附近）。
   缺的只是工具本身和把配置接进来。
2. `capability.ts` 里 `web.tools = []`，`declaredOnly()` 因此一直把 `web`
   列成「声明了、还没实现」。
3. 工具执行前的网关在 `agent.ts` 的 `gateToolCall`：`kindOf(tool)` 给出
   `net`，`actionTarget` 给出目标（MCP 用 server 名）。`web_fetch` 的 target
   应当是**主机名**，不是完整 URL —— policy 比的是域名。
4. 关键约束（与 skill 相反）：web 结果是**工具结果**，必然进 checkpoint；
   这没问题 —— 它不是每轮都在的固定文本，只在本轮之后多一条 ToolMessage。

## 1. 配置

`hive.config.json` 追加一段（与 `mcp` / `skills` 同级）：

```json
{
  "web": {
    "allowDomains": ["example.com", "*.wikipedia.org"],
    "agents": ["A"]
  }
}
```

| 规则 | 做法 |
|---|---|
| 白名单 | 并入 `policy.net.allowDomains`；`HIVE_POLICY_NET` 设了就以 env 为准（与 `mcp.allowServers` 同一条「env 显式覆盖文件」） |
| 匹配 | 精确域名；`*.example.com` 匹配 `example.com` 与任意子域；`*` = 不限（自担风险）；大小写不敏感、末尾点忽略 |
| 装配 | `web.agents`（默认 `['A']`）决定哪些身份装 `web_fetch`；没写 `web` 段 = 0 工具 = 0 token |
| 空白名单 | 段配了但 `allowDomains` 为空：**工具照装**（模型看得见这个能力），调用一律被 policy 拒，启动时给一条警告 |
| 写坏 | 与 settings 其它段一致：整份忽略并说原因（宁可少开能力） |

`web.agents` 不是白名单的一部分：它决定「装不装」，`net.allowDomains` 决定
「能不能去」。两层都要过 —— 与 `mcp.servers` / `mcp.allowServers` 同构。

## 2. 工具契约

名字 `web_fetch`，参数只有一个：

```ts
z.object({ url: z.string().describe('完整 URL，例如 https://example.com/page') })
```

行为约束（工具层自己兜底，不依赖网关）：

| 项 | 规则 |
|---|---|
| 方法 | 只 GET |
| 协议 | 只 `http:` / `https:` |
| 端口 | 只默认端口（http 80 / https 443） |
| userinfo | 拒绝 `user:pass@host` |
| IP 字面量 | 拒绝直接访问 IP（IPv4 / IPv6 都算） |
| DNS | `lookup` 全部地址，**任一**落在私网/回环/链路本地/组播/保留段就拒 |
| 重定向 | 手动跟随，最多 5 跳；**每一跳重新过白名单 + 私网检查**；跨域跳转不豁免 |
| 大小 | 默认 2 MiB（`HIVE_WEB_MAX_BYTES`），超限截断并标注 |
| 超时 | 默认 15s（`HIVE_WEB_TIMEOUT_MS`），整条重定向链共用一个 AbortSignal |
| 类型 | 只读 `text/*`、`application/json`、`application/xml`、`+json` / `+xml`；其它类型只回元信息，不读正文 |
| 输出 | 纯文本：URL / 状态 / 类型 / 字节（截断标注）/ 正文 |

不做什么：POST、表单、认证头、Cookie、浏览器渲染、HTML 转 Markdown、
Robots 解析、缓存。这些都该由 MCP server 或后续能力补，不塞进这一件工具。

## 3. 缓存账

| 变化 | 谁的前缀作废 | 何时 |
|---|---|---|
| `web_fetch` 工具 schema | 只作废 `web.agents` 里的身份 | 一次性（启动装配） |
| 一次抓取 | 不作废前缀；本轮之后多一条 ToolMessage | 每次调用 |
| 改白名单 | 不作废前缀；下一次调用按新 policy 判 | `HIVE_POLICY_NET` / 重启 |

工具描述保持短：它每轮都在装了 web 的身份的前缀里。

## 4. policy 与安全

- 网关判定：`kind = net`，`target = hostname`。放行条件 = 身份有 `web`
  capability + `domainAllowed(host, spec.net.allowDomains)` + 规则表不是 deny。
- 工具层再查一次同一个 `domainAllowed` 与私网地址 —— 两层同源，
  直接调用工具（测试、嵌入）也出不去。
- DNS rebinding 只能做到 best effort：解析一次、检查一次，`fetch` 内部会再解析。
  这是 Node 内置 fetch 不暴露 `lookup` 的代价，写在这里而不是假装没有。
- 不落正文到账本；policy 行只记 host 与判定。

## 6. 零 API 测试清单

1. URL：拒 ftp、userinfo、IP 字面量、非默认端口；接受正常 URL、去尾点、大小写归一
2. 白名单：精确、`*.` 子域、`*`、空、大小写、末尾点
3. 私网：10/8、127/8、169.254/16、172.16/12、192.168/16、100.64/10、::1、fc00::/7、fe80::/10
4. 配置：`web.allowDomains` 必须字符串数组、`agents` 默认 `['A']`、坏字段整份失败
5. 抓取（注入 fake fetch / fake lookup，不联网）：白名单外拒绝、私网拒绝、
   200 文本返回、超限截断、重定向出白名单拒绝、超过最大跳数拒绝、非文本类型不读正文
6. 装配：`activateWeb` 后指定身份有 `web_fetch`、别的身份没有；`declaredOnly` 不含 `web`
7. 网关：`net` 动作按白名单放行/拒绝；`*.` 通配在网关同样生效

真机验收（需要网络与 key）：配一个域名 → 模型 `web_fetch` 一个真实页面 →
`/policy log` 看到 allow 行；把域名从白名单去掉 → 同一调用变 deny。
