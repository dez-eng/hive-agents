# hive v4 · M4.2b 设计 —— skill 装载

> 一句话：把一段**方法论文本**按需挂到本轮用户消息的末尾 —— 不进 system 前缀、
> 不进 checkpoint、不热插拔清单。
>
> 约束来自 `docs/V4-PLAN.md` §3.3：skill 必须挂在用户消息末尾（与角色片同位置），
> 文本按需装载，不进 checkpoint。本文只定接口与字节位置。

## 0. 现状（代码事实）

1. **角色片的处理方式不能照抄**。`run()` 里 `renderUserContent(req.text, req.module)`
   产出的字符串直接作为 `HumanMessage` 进图（`agent.ts:749`、`:785`）——
   也就是说**角色片会进 checkpoint**。skill 明确要求「不进 checkpoint」，
   所以挂载点必须是**发送视图**，不是 state。
2. **发送视图只有一个现成入口**：`callModel` 每次从 state 取 `messages`，
   前置 `new SystemMessage(STABLE_PREFIX)` 再发（`agent.ts:605`）。
   M2.5 的压缩也在这里只改要发出去的那一份（`state / checkpoint 一个字节不改`）——
   skill 走同一条路。
3. **工具 schema 是前缀的一部分**：`toolsFor(agent)` 在 `buildGraph` 时装配，
   `CAPABILITY_ORDER` 决定顺序；动态注册的现成样例是 `registerMcpTools`。
4. **网关判定靠静态表**：`TOOL_ACTION` 里没有映射 = 不进网关（如 `calculator`）。

## 1. 来源与冻结

配置文件 `hive.config.json` 追加一段（与 `mcp` 同级）：

```json
{
  "skills": {
    "dir": ".hive/skills",
    "agents": ["A"]
  }
}
```

| 规则 | 做法 |
|---|---|
| 目录 | 只扫 `dir` 这一层，**不递归**；默认 `.hive/skills`（相对 cwd） |
| 文件 | 只认 `*.md`；文件名去掉 `.md` 即 skill 名，须匹配 `^[A-Za-z0-9._-]+$` |
| 标题 | 第一条 `# ` 行；没有就用文件名 |
| 上限 | 单个文件默认 ≤ 64KB，`HIVE_SKILL_MAX_BYTES` 可调；超限跳过并警告 |
| 冻结 | **启动时一次性读进内存**，运行中改文件不生效（与 MCP 同一条自律） |
| 坏文件 | 跳过并给一条警告，不阻塞启动（与 settings / MCP 的失败态度一致） |

目录不存在不是错误：0 个 skill = 0 token，`/skills` 会说清楚。

## 2. 装载

两个入口，写的是同一份 **thread 级状态**：

| 入口 | 形态 | 用途 |
|---|---|---|
| 模型 | 工具 `load_skill({ name })` | 按需：读到任务相关时自己装 |
| 人 | `/skill load <name>`、`/skill off`、`/skill list` | 显式控制；不受身份 capability 限制 |

- `load_skill` **只接受冻结清单里的名字**，不做任何路径拼接 → 不存在任意文件读取。
- 未知名字的返回里带上当前可用名字（模型一次就能纠正）。
- `skills.agents`（默认 `['A']`）决定哪些身份装这件工具，走既有的
  `enableXxxFor` + `toolsFor` 装配，与 MCP 完全同构。
- 装载状态按 `threadId` 存（`HiveAgent` 内一张 `Map`）：`/new` 换 thread 等于没装
  （与历史一样冷启）；独立会话 `solo#X` 各装各的；进程退出即消失。

## 3. 挂载位置（字节级）

`callModel` 组装 `messages` 时：

```
[SystemMessage(STABLE_PREFIX)]
  + packed.messages 的克隆
  + 找到**最后一条 HumanMessage**，在它的 content 末尾追加：
      "\n\n【skill:<name>】\n" + <skill 全文>
```

三条理由：

1. **不进 state**：只是 `new HumanMessage({...})` 的克隆，checkpoint 里那条消息
   仍是原文。
2. **贴在用户消息末尾，不另起一条**：本轮的工具轮里 state 末尾是 `ToolMessage`，
   在它后面插一条会变成「新的用户输入」，破坏消息序列；而本轮的用户消息在历史里
   一直都在，追加到它末尾，工具轮也能继续看到 skill。
3. **与角色片同侧**：两者都在「必然未命中」的尾巴里，边际成本 ≈ 0。

关闭方式：`/skill off` 或 `/tail off` 的先例不适用 —— 后者只针对角色片；
skill 自己一条开关（`/skill off`）。没有装载时发送字节与现在**完全一致**。

## 4. 缓存账

| 变化 | 谁的前缀作废 | 何时 |
|---|---|---|
| `load_skill` 工具 schema | 只作废 `skills.agents` 里那些身份 | 一次性（启动注册时） |
| 装载 / 卸载 skill | 不作废已命中前缀；仅本轮用户消息之后的部分重算 | 每次装载 |
| 同一 skill 的工具轮之间 | 第二轮起命中（skill 文本字节不变） | — |
| 改 skill 文件 | 不生效，直到重启 | 冻结清单 |

`/misscheck` 不需要改：skill 文本随用户消息计入 `inTok`，账本自然看得到。

## 5. policy 与安全

- `load_skill` **不进 `TOOL_ACTION`**：它只返回冻结清单里的文本，无副作用，
  与 `calculator` 同类。
- 能装 ≠ 能读任意文件：名字白名单 + 启动时读入，运行中不再碰文件系统。
- 身份级收权：`AGENTS[i].capabilities` 没有 `skill` 就没有这件工具；
  `/skill` 是人手动操作，只影响当前 thread。
- 不做：远程拉取、递归扫描、版本管理、运行中热更新。

## 6. 可观测

| 位置 | 内容 |
|---|---|
| `/skills` | 目录、冻结数量、每个 skill 的名字/标题/字节、当前 thread 装的是哪个 |
| `/doctor` | 一行：`skill  <dir> · N 个 · 已装 <name|—>` |
| `/caps` | `skill` 不再出现在「声明了但还没实现」里 |
| 警告 | 坏文件 / 超限 / 重名，都在启动时打到 stderr，一条一个原因 |

## 7. 零 API 测试清单

1. 扫描：只认 `*.md`、不递归、非法文件名跳过、标题取第一条 `# `
2. 配置：`skills.dir` 必须非空字符串、`agents` 必须字符串数组、写坏给原因
3. 工具：`load_skill` 只接受清单内名字；未知名字返回可用列表
4. 挂载：假模型收到的最后一条 HumanMessage 含 `【skill:…】`，
   而 `agent.history(thread)` 里**不含** skill 全文
5. 工具轮：第二次模型调用仍能看到 skill
6. 装配：`skills.agents` 之外的身份没有 `load_skill`；`/caps` 不再列为未实现
7. 命令：`/skill list|load|off` 的状态流转
8. 缓存：装载前后 `toolsCharsFor` 的增量只落在装了的身份上

真机验收（需要 key，单独一条）：装一个 skill → 一轮问答 → `/ledger` 看入 token
增加量 ≈ skill 字节 / 3，`/misscheck` 的未命中增量落在尾巴。
