# hive v3 · M3.5 设计 —— B 主动反问 A

> 一句话：把「子 agent 只能被父追问」升级为「子 agent 可以中途向父提问」。
> 用**暂停-续跑**实现，不做真并发回调。
>
> M3 拍板先做「父驱动往返」，M3.5 补上反方向那半程。`@B` 寻址 / 广播仍然不做
> （V3-PLAN §7 已拍板不上总线）。

## 0. 为什么不做「真回调」

现状是一个同步调用栈：

```
父 run() ──handleDelegate()──▶ runSubagent() ──await runner.run()──▶ 子 run()
                                                                    │
                                                   子模型调 ask_parent
                                                                    │
                                          「等父回答」必须让父模型在
                                          子 run 内被调用 —— 父此刻
                                          正阻塞在 await 上 → 死锁
```

LangGraph 的图内没有双向通道；父模型的一轮调用在 `delegate` 工具执行期间是
阻塞的。要做真回调，得引入事件循环 + 父图 re-entry + 跨 runtime 的问答队列，
那是另一套并发模型（且与 `AsyncLocalStorage` 的 run 隔离相互打架）。

**暂停-续跑**复用 M3 已经落地的 `resume` 机制，不新增并发原语：

```
父 ──delegate(goal/slice/expect)──▶ 子 thread
                                      │ 子模型调 ask_parent({question})
                                      ▼
父模型收到 ToolMessage：子任务暂停 + 问题
                                      │
父 ──delegate(resume=taskId, goal=回答)──▶ 同一个子 thread 继续
```

代价与收益都要说清：

| | 暂停-续跑 | 真回调 |
|---|---|---|
| 父模型能否在子任务运行中回答 | 不能（要等子任务让出） | 能 |
| 新增并发原语 | 0 | 事件队列 + 图 re-entry |
| 与 M3 resume 的关系 | 同一套 | 另起一套 |
| 子任务能否连续追问多轮 | 能（每轮都暂停） | 能 |
| 实现风险 | 低 | 高（死锁 / 串账） |

## 1. 现状（代码事实）

1. `agent.ts` 的 `callTools` 已经有一个执行层特判的先例：`delegate` 不走工具函数，
   而是交给 `handleDelegate`。`load_skill` 同样特判。`ask_parent` 是第三件。
2. `TurnResult` 目前只有 `text / sentContent / meter / budgetHit / denied / steps / compacted`，
   没有「本轮为什么停」的字段 —— 要加一个可选的 `question`。
3. `HandoffResult`（`handoff.ts`）已经有 `thread` 这个 M3 加的可选字段；
   `question` 用同样方式追加，旧调用方不受影响。
4. 子任务与父任务的区分目前只有 `delegate` 上下文：它表示「本轮能借调谁」，
   不表示「本轮有没有父」。需要新增 `parent`（`{ from, taskId }`）。
5. `afterTools` 已经能结束本轮（步数护栏走同一条路）。`ask_parent` 复用它：
   设了 `runtime.question` 就返回 `END`。

## 2. 接口

### 2.1 工具

```ts
// src/core/dialog.ts
export const ASK_TOOL = 'ask_parent';
export const askParentTool = tool(
  async () => 'ERROR: ask_parent 只在借调子任务里由执行层处理',
  {
    name: ASK_TOOL,
    description: '向发起这次借调的父会话提问；本轮会暂停，父回答后用 delegate(resume=…) 继续。',
    schema: z.object({ question: z.string().describe('要问父会话的问题，一句话说清缺什么') }),
  },
);
```

- 无副作用、不读写文件、不联网 —— **不进 `TOOL_ACTION`**（与 `calculator` 同类）。
- 真实行为在 `agent.ts` 的 `callTools` 里特判；直接调用工具只得到一句说明。

### 2.2 运行时字段

```ts
// agent.ts
export interface ParentContext {
  /** 父会话的身份（谁发起的这次借调） */
  from: AgentId;
  /** 父会话手上的 taskId —— 回答时用它 resume */
  taskId: string;
}
export interface TurnRequest {
  // …既有字段
  parent?: ParentContext;
}
export interface TurnResult {
  // …既有字段
  /** 本轮因 ask_parent 暂停时的问题；没有就是普通结束 */
  question?: string;
}
```

`GraphRuntime` 加 `parent: ParentContext | null` 与 `question: string | null`。

### 2.3 交接结果

```ts
// handoff.ts
export const HandoffResultSchema = z.object({
  // …既有字段
  question: z.string().optional(),
});
```

`subagent.ts` 把子轮的 `TurnResult.question` 透传到 `HandoffResult.question`，
`notes` 写「暂停等上级回答」。

### 2.4 父侧话术

`formatDelegateResult` 在 `question` 存在时输出：

```
[B·t003-abcd 暂停 812 token] 子任务需要你回答：<question>
回答后用 delegate(resume="t003-abcd", goal="<回答>") 继续。
```

- 明确给出 `taskId` 与下一步调用形状 —— 模型不必再查 `/handoffs`。
- 预算熔断优先于问题（熔断说明这一轮没跑完，问题可能不完整）。

## 3. 装配与缓存

| 变化 | 谁的前缀作废 | 何时 |
|---|---|---|
| `ask_parent` 的 schema | 装它的身份（B/C/D） | 一次性（升级后首次启动） |
| `delegate` 的 schema | 不变 | — |
| A 的工具集 | 不变（A 不被借调，不需要反问） | — |

- 新 capability `ask` 放在 `CAPABILITY_ORDER` **最后**（`mcp` 之后）：追加在末尾
  不改变前面任何字节，已命中的前缀仍命中。
- `AGENTS` 默认给 B/C/D 加 `ask`；A 不加。原因是 A 是借调的发起方，
  它没有「父」，装了也只是多一件用不上的工具。
- `ask` 不是权限：它能说的只有「一句话问题」，不能读文件、不能改状态。

## 4. 边界

| 场景 | 行为 |
|---|---|
| 独立会话（`hive --as B`）调 `ask_parent` | 返回 `ERROR: 当前没有父会话`（没有 `parent`） |
| 主控 A 调 `ask_parent` | 同样拒绝 —— A 没有父 |
| 子任务在同一批 tool_calls 里既调 `ask_parent` 又调别的 | 其它工具照常执行；本轮在 `afterTools` 结束 |
| 问题为空 | 工具参数校验拦下（zod 非空字符串） |
| 问题过长 | 截断到 2000 字符（防止把父上下文一次性打爆） |
| 父不回答、直接结束 | 子会话留在 checkpoint 里；`/handoffs` 能看到，之后仍可 `resume` |
| 多次暂停 | 每次都是一个新 `HandoffResult.question`，同一 taskId 可反复 resume |
| 预算 | 暂停那一轮照常记账、扣令牌；续跑再走一次授权 |

## 5. 不做

- 真并发回调 / 事件总线
- 子 agent 直接向用户提问（必须经过父，权限边界不越过一层）
- 广播 / `@` 寻址
- 跨进程的父会话恢复（同一进程内 resume，进程退出即结束）

## 6. 零 API 测试清单

1. 装配：B/C/D 有 `ask_parent`，A 没有；`/caps` 的 `declaredOnly` 不受影响
2. 子会话：`TurnRequest.parent` 存在 + 模型调 `ask_parent` → `TurnResult.question`
   等于问题原文，本轮 `afterTools` 结束（假模型只被调用一次）
3. 没有父：A 调 `ask_parent` → 工具结果是一句 ERROR，`TurnResult.question` 为空
4. 交接透传：`HandoffResult.question` 从子轮带出，`notes` 标记暂停
5. 父侧话术：`formatDelegateResult` 含 taskId、问题与 `resume` 提示
6. 续跑：带 `question` 的 handoff 仍可用 `continueSubagent` 回答，同一 thread
7. 截断：超长问题被截到 2000 字符
8. 回归：既有 delegate / resume / 并行借调测试全绿

真机验收（需要 key，单独一条）：A 派 B 做一个信息不足的任务 → B 调
`ask_parent` → A 看到问题 → A `delegate(resume=…)` 回答 → B 继续完成。
